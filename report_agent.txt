# Code Review Report

## SECTION 1 — Linter Findings Explained

**Line 1: `import os,sys`**
- **E231 missing whitespace after ','** — When you separate items with a comma, PEP 8 wants a space after it for readability: `import os, sys`.
- **E401 multiple imports on one line** — PEP 8 recommends one import per line (except for `from x import a, b`). This makes it easier to see, diff, and remove individual imports later. Fix:
  ```python
  import os
  import sys
  ```

**Line 2: `def CalculateTotal( items ):`**
- **E302 expected 2 blank lines, found 0** — PEP 8 says top-level function and class definitions should be separated from surrounding code by **two** blank lines. This function immediately follows the `import` lines with no spacing.
- **E201 whitespace after '('** and **E202 whitespace before ')'** — This directly matches the PEP 8 "Pet Peeves" rule: *"Avoid extraneous whitespace immediately inside parentheses, brackets, or braces."* Write `def CalculateTotal(items):` instead of `( items )`.

**Line 3: `Total=0`**
- **E225 missing whitespace around operator** — Binary operators like `=` need a space on each side: `Total = 0`. PEP 8's example shows `i = i + 1`, not `i=i+1`.

**Line 8: `class shopping_cart:`**
- **E302 expected 2 blank lines, found 1** — Same rule as before; the class definition needs two blank lines above it since a function definition precedes it.

**Line 9: `def __init__(self,name):`**
- **E231 missing whitespace after ','** — Same comma-spacing rule: `def __init__(self, name):`.

**Line 10: `self.name=name`**
- **E225 missing whitespace around operator** — Again, spaces are required around `=`: `self.name = name`.

**Line 12: `def add( self,item ):`**
- **E301 expected 1 blank line, found 0** — Inside a class, methods should be separated by **one** blank line each. This method directly follows `__init__` with no spacing.
- **E201 / E202** — Same "no space just inside parentheses" issue as before.
- **E231** — Same missing space after comma issue (`self,item` → `self, item`).

**Line 15: `c = shopping_cart("Anoop")`**
- **E305 expected 2 blank lines after class or function definition, found 1** — Just like E302 protects space *before* defs, E305 protects space *after* them. Code that runs after a class/function block needs two blank lines of separation to visually mark "we've left the definition and are now in script logic."

**Line 18: `print( CalculateTotal(c.x) )`**
- **E201 / E202** — same inside-parentheses whitespace issue.
- **W292 no newline at end of file** — Every text file (including `.py` files) should end with a newline character. Many tools and version control systems expect this; without it, some editors/terminals will show odd behavior or diffs.

## SECTION 2 — Issues the Linter Can't Catch

These won't show up as lint errors, but they matter for readability and following Python conventions (PEP 8 naming rules, PEP 257 docstring conventions):

1. **Function naming (`CalculateTotal`)** — PEP 8 says functions should be `lower_case_with_underscores`. This should be `calculate_total`. `CalculateTotal` looks like a class name (CapWords), which is confusing.

2. **Class naming (`shopping_cart`)** — PEP 8 says classes should use `CapWords` (a.k.a. PascalCase): `ShoppingCart`, not `shopping_cart`. Right now the naming conventions for the class and function are essentially swapped from what's expected.

3. **Variable naming (`Total`)** — Local variables should be lowercase: `total`, not `Total`. Capitalized names are conventionally reserved for classes or constants.

4. **Unclear attribute name (`self.x`)** — Calling the cart's list of items `x` gives no hint about what it holds. Something like `self.items` would be self-documenting and make `CalculateTotal(c.x)` read as `calculate_total(c.items)` — much clearer.

5. **No docstrings** — PEP 257 recommends every public module, class, and function have a docstring explaining its purpose, parameters, and return value. None of `CalculateTotal`, `shopping_cart`, `__init__`, or `add` have one. Even a one-liner helps:
   ```python
   def calculate_total(items):
       """Return the sum of all numeric values in items."""
   ```

6. **Unused imports** — `os` and `sys` are imported but never used
